## Specification-only versus ExecutionContext

Mesmo sem liberar mutation, a comparação analítica é concreta:

| Dimensão | Specification isolada | Azevedo v0.6 |
| --- | --- | --- |
| Intenção | Objetivos, critérios e decisões pendentes | Mesma autoridade preservada, com blockers tipados |
| Scope | Estrutura de arquivos sugerida | Paths observados, confidence e entry flow ligados a evidence ids |
| Arquitetura | Proposta narrativa | Contratos, use case, TypeSafe, mapper e resolver atuais relacionados |
| Risco | Regras LGPD e segurança | Risk `critical` preservado e findings vinculados ao código |
| Verification | Lista desejada de testes | Scripts reais disponíveis versus typecheck ausente |
| Disciplina | Recomendações humanas | Write denial, worktree requirement, scope expansion explícita e três attempts no máximo |
| Expertise ECC | Não selecionada por task | Units de implementation, scope, TDD, verification, failure, recovery e change evidence |

O ganho demonstrado nesta execução é impedir uma implementação plausível, porém não autorizada, enquanto entrega ao próximo ciclo paths, constraints, risk e verification reais. A prova de code changes + verification fica deliberadamente pendente, não simulada.
